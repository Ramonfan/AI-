# Mini AI Notes 项目规则

这份规则用于约束后续实现方式。每次写代码前先检查一遍。

---

## 1. OpenSpec 先行

每个功能、每一课、每次明显变更，都先写 OpenSpec，再实现代码。

OpenSpec 存放位置：

```text
openSpec/
```

OpenSpec 必须说明：

- 背景
- 目标
- 非目标
- 用户故事
- 功能需求
- 非功能需求
- API / 框架依赖
- 验收标准
- 验证方式
- 学习要点
- 复盘

如果没有 OpenSpec，不开始实现。

---

## 2. SuperPowers 约束执行

每次开发都按 SuperPowers 检查清单执行。

SuperPowers 存放位置：

```text
superPowers/
```

核心约束：

- Spec First：先规格后实现
- Context First：先查 API 后编码
- Mock First：先 Mock 后真实 API
- Small Step：小步推进
- Verify Always：必须验证
- Chinese Notes：中文沉淀
- Safe Keys：密钥安全
- Python Backend：后端统一 Python
- Moya Network：iOS 网络层统一使用 Moya / Alamofire

开发前后都要检查：

```text
superPowers/implementation_checklist.md
```

---

## 3. API 先查文档

凡是涉及框架、库、SDK 或 API 的实现，先使用 Context7 查询当前文档，再写代码。

适用场景：

- SwiftUI 组件和状态管理
- Moya、Alamofire、async/await、流式请求
- FastAPI 路由、请求体、文件上传、StreamingResponse
- OpenAI SDK、Responses API、Structured Outputs、Tool Calling
- pgvector、Qdrant、数据库 API
- 任何不确定签名或版本行为的库

流程：

```text
resolve-library-id
→ query-docs
→ 读当前 API 用法
→ 再写代码
→ 在课程笔记里记录用到的 API
```

---

## 4. 每次只推进一个小目标

不要一口气做完整 AI App。

每次实现都只围绕当前课程目标：

```text
第 1 课只做 UI 和 Mock
第 2 课只做本地 Service 抽象
第 3 课才接后端
第 4 课才做 Structured Outputs
```

---

## 5. 先 Mock，后真实 API

每个新能力都先用 Mock 跑通。

原因：

- UI 状态更容易验证
- 不浪费 token
- 方便测试失败状态
- 接真实 API 时边界更清楚

---

## 6. iOS 不保存模型 API Key

真实模型 API Key 只能放在后端或本地开发环境变量里。

iOS 客户端只调用自己的后端 Proxy。

---

## 7. iOS 网络层统一使用 Moya / Alamofire

本项目 iOS 网络请求统一使用 Moya，底层网络能力由 Alamofire 提供。

iOS 网络技术约束：

- 网络抽象：Moya `TargetType`
- 请求入口：Moya `MoyaProvider`
- 底层网络：Alamofire
- JSON 编解码：Swift `Codable`
- 状态承接：ViewModel 只接收业务结果或可读错误
- 安全边界：iOS 不保存模型 API Key，只调用 FastAPI 后端 Proxy

实现要求：

- 新接口先定义 API Target，不在 View 或 ViewModel 中直接拼 URL。
- 网络错误、后端错误、解码错误集中在 Service 层转换。
- ViewModel 不直接依赖 Alamofire / Moya 细节，只依赖 `SummaryService` 协议。
- 除非先更新 OpenSpec，否则不新增另一套 iOS 网络框架。
- 后续如需要请求日志、插件、重试、鉴权 header，优先通过 Moya Plugin 或 Provider 配置扩展。

---

## 8. 后端统一使用 Python

本项目后端统一使用 Python 实现，默认框架为 FastAPI。

后端技术约束：

- 语言：Python
- Web 框架：FastAPI
- 数据模型：Pydantic
- 服务启动：uvicorn
- AI 调用：OpenAI Python SDK
- 配置来源：环境变量或 `.env`，不写死密钥

除非先更新 OpenSpec，否则不切换到 Node.js、Go 或其他后端技术栈。

---

## 9. 每课都要有验收

每节课结束必须完成：

- 功能能运行
- 至少一个失败状态
- 一段中文学习笔记
- 当前任务清单更新
- openSpec 状态更新
- 能用中文讲清楚本课流程

---

## 10. 每个流程结束要按 AI 应用流程整理笔记

每完成一个功能流程、课程节点或明显阶段，都必须按 `docs/AI应用开发流程笔记模型.md` 整理笔记。

正式学习笔记统一沉淀到独立 Git 仓库：

```text
/Users/leigod/雷神/技术探索/AI应用学习笔记/AI-
```

该仓库用于同步到 GitHub。MiniAINotes 项目内的 `docs/` 可以保留项目过程文档，但面向复习和长期沉淀的笔记以后以独立笔记仓库为准。

笔记重点不是流水账，而是回答：

- 这个技能在 AI 应用开发流程中处在哪一环？
- 它的上游输入是什么？
- 它的下游输出是什么？
- 它解决了什么工程问题？
- 它失败时会影响哪个环节？
- iOS、后端、AI 应用、工程化分别要掌握什么？

总结必须包含：

- 本轮做了什么流程
- 这个流程背后的核心工程思想
- 它在 AI 应用开发流程中的上游、当前环节和下游
- iOS 侧需要关注的知识点
- 后端侧需要关注的知识点
- AI 应用侧需要关注的知识点
- 下一步最值得补的 1 到 3 个能力

输出格式固定为：

```text
本轮流程：

核心思想：

它在 AI 应用开发流程中的位置：
- 上游：
- 当前环节：
- 下游：

需要关注的技能知识点：
- iOS：
- 后端：
- AI 应用：
- 工程化：

下一步建议重点学习：
1.
2.
3.
```

注意：这不是泛泛复盘，而是面向学习路径的技能定位。要指出“为什么这个知识点现在值得学”，避免只列名词。每篇正式课程笔记优先使用完整课程模板；临时学习到的小知识可以使用技能卡片模板。

# 第 10 课：财报分析 RAG 上下文

## 这一课做什么

这一课先做 RAG v0：不急着引入向量数据库和 Embedding，而是在后端放一组本地财报阅读知识片段，用关键词检索把相关片段附加到财报分析结果里。

核心流程是：

```text
iOS 输入公司名
-> 后端 Provider 获取结构化财报事实
-> 本地 Retriever 根据指标、摘要、风险和追问检索知识片段
-> 后端把 Provider 事实 + retrieved_contexts 交给 AI 或规则解读
-> iOS 展示财报结果和“参考知识”
```

## 为什么先做关键词 RAG

RAG 的关键不是一上来就用向量库，而是先把“检索上下文进入业务链路”这件事跑通。

这一课故意只用 Python 标准库做三件事：

- 维护一组可解释的本地知识片段。
- 根据财报分析结果拼出检索 query。
- 返回 top 3 片段，并带上 `source_id`、`title`、`text`、`score`。

这样调试时能直接看到：为什么命中这条知识、分数来自哪里、AI 或规则层拿到了什么上下文。

## 后端新增内容

新增 `app/rag_service.py`：

```text
FinancialReportAnalysisResponse
-> build_financial_report_context_query
-> retrieve_contexts_for_query
-> attach_retrieved_contexts
```

知识库目前覆盖：

- 收入增长拆解
- 毛利率与成本压力
- 经营现金流和利润质量
- 资产负债表韧性
- 风险与业务驱动因素
- 管理层指引

普通接口 `/api/financial-report/analyze` 和流式接口 `/api/financial-report/analyze/stream` 都会在 Provider 成功后附加 `retrieved_contexts`。

## AI 和规则层怎么用上下文

非流式 AI 解读和流式 AI 解读都会通过 `build_financial_report_narrative_input` 收到：

```text
retrieved_contexts: [...]
```

没有 OpenAI Key 或模型不可用时，规则降级文本也会显示“参考知识”，所以不消耗额度也能验证 RAG 链路。

## iOS 新增内容

iOS 新增：

```swift
FinancialReportContextSnippet
FinancialReportAnalysis.retrievedContexts
```

`retrieved_contexts` 使用 `decodeIfPresent`，旧后端不返回该字段时会默认解码为空数组。

结果页在存在上下文时显示“参考知识”区块，每条展示标题、正文和检索分数。

## 这课要掌握的点

- Provider 事实和 RAG 知识不是一回事：前者回答“这家公司发生了什么”，后者提供“怎么阅读这些事实”的解释框架。
- RAG 结果要可见，否则很难判断模型是否真的基于上下文工作。
- 先用关键词检索跑通接口契约，再升级 Embedding / 向量数据库，学习路径更稳。

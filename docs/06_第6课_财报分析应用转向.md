# 第 6 课：转向财报分析应用

本课目标：把应用从“笔记总结”调整为“输入公司名字，分析默认最新财报”。

## 1. 新产品链路

```text
iOS 输入公司名
-> FastAPI 后端
-> 后端查找最新财报
-> 后端提取财报结构化数据
-> AI 生成中文分析
-> iOS 展示结构化结果
```

第一版先不接真实 SEC 数据，先用 Mock 固定前后端契约。

## 2. 为什么先 Mock

财报分析会涉及多个不稳定点：

```text
公司名 -> ticker / CIK
CIK -> 最新 10-K / 10-Q
财报 -> XBRL 指标
指标 -> AI 分析
```

如果一上来全部接真实数据，任何一个环节失败都会影响学习。先 Mock 可以把 iOS 页面、后端接口、结构化返回固定下来。

## 3. 后续真实数据源

后续优先接 SEC EDGAR：

```text
submissions API：获取公司提交历史
companyfacts API：获取 XBRL 财务事实
```

SEC 官方文档说明 `data.sec.gov` 提供 JSON REST APIs，并且不需要 API Key；但它不支持 CORS，所以 iOS 不直接访问 SEC，仍然由 Python 后端 Proxy 获取。

## 4. 第一版接口

```text
POST /api/financial-report/analyze
```

请求：

```json
{
  "company_name": "Apple"
}
```

响应：

```json
{
  "company_name": "Apple",
  "ticker": "AAPL",
  "filing_type": "10-Q",
  "fiscal_period": "FY2025 Q3",
  "filing_date": "2025-08-01",
  "summary": "这是一份用于学习阶段的 Mock 财报分析。",
  "metrics": [
    {
      "name": "Revenue",
      "value": "$85.8B",
      "interpretation": "收入保持增长，说明核心业务仍有韧性。"
    }
  ],
  "highlights": ["收入增长稳定"],
  "risks": ["硬件需求波动可能影响未来季度"],
  "follow_up_questions": ["毛利率变化来自产品结构还是成本变化？"],
  "disclaimer": "仅供 AI 应用学习，不构成投资建议。"
}
```
